# 硬件架构与接线说明

> 本文档说明「基于多模态感知的智能汽车无感交互与安防系统」的整体框架、实现步骤、各硬件作用，以及**谁接在谁上、物理如何连线**。所有引脚均来自工程源代码实测，非示意。

---

## 一、系统总框架

系统分三层：**感知层（多块 ESP32）→ 中枢层（树莓派5）→ 执行层（门锁/摄像头/灯/云）**。

```
                          感知层 (ESP32 节点)                               中枢层           执行层
 ┌──────────┐  BLE   ┌──────────┐  BLE   ┌──────────┐  BLE   ┌───────────────┐
 │  BLE1    │ ─────▶ │  BLE2    │ ─────▶ │  BLE3    │ ─────▶ │    anchor     │
 │ 雷达节点1 │ notify │ 雷达节点2 │ notify │ 雷达节点3 │ notify │  车端主控 ESP32 │
 │ +LD2450  │        │ +LD2450  │        │ +LD2450  │        │  (系统大脑)    │
 │          │        │ +PN532   │        │          │        │  +DW3000 UWB   │
 │          │        │ +继电器门锁│        │          │        │  +MPU6050 IMU  │
 └──────────┘        └────┬─────┘        └──────────┘        └───┬───────┬───┘
                          │ NFC刷卡直接开锁                  UART2 │       │ GPIO4 擦碰信号线
                          ▼                                115200 │       ▼
                       [电磁门锁]                                  │   ┌──────────┐  WiFi   ┌──────────┐
                                                                  │   │thingscloud│ ──────▶ │ThingsCloud│→ 微信预警
   ┌──────────┐   UWB 双向测距(DS-TWR)                            │   │  ESP32   │  MQTT   │  云平台   │
   │   tag    │ ◀───────────────────────────────────────────────┤   └──────────┘         └──────────┘
   │ 车主标签  │      (测车主与车的距离 + 按键开关门指令)            │
   │ +DW3000  │                                                  ▼
   └──────────┘                                        ┌───────────────────┐
                                                       │     树莓派 5        │
                                                       │  /dev/ttyAMA0 ↔UART │
                                                       │  Qt 车载UI + 调度   │
                                                       │  Python 人脸识别    │
                                                       └───┬───────────────┘
                                                    USB    │  ×4
                                                           ▼
                                                   [4 路摄像头 video0/2/4/6]
```

**一句话数据流**：3 个毫米波雷达各测到车周围行人坐标 → 经 BLE 菊花链汇聚到 anchor → anchor 用 UWB 判断"是不是车主本人在靠近"、用 IMU 判断"是否被擦碰"，融合后经串口发给树莓派 → 树莓派 Qt 显示 + 调度摄像头/人脸识别 → 触发开关门、录像、云预警。

## 二、硬件清单：每个硬件干嘛的

| 硬件 | 型号 | 挂在哪个节点 | 作用 |
|---|---|---|---|
| 车端主控 | ESP32 (esp32dev) | **anchor** | 系统大脑：汇聚雷达、跑 UWB 测距、擦碰检测、串口上传树莓派 |
| 车主标签 | ESP32 + DW3000 | **tag** | 车主随身"电子钥匙"，与 anchor 做 UWB 测距，带开/关门按键 |
| UWB 模块 | DW3000 | anchor、tag 各一 | 厘米级测距，判断车主与车的距离（1m 开门 / 2m 关门）|
| 毫米波雷达 | 海凌科 HiLink LD2450 | BLE1/BLE2/BLE3 各一 | 探测车周围行人的 X/Y 坐标与速度（电子围栏）|
| 雷达采集节点 | ESP32 ×3 | BLE1/BLE2/BLE3 | 各接一个雷达，BLE 级联把 3 个目标坐标传给 anchor |
| NFC 读卡器 | PN532 | BLE2 | 刷授权卡开门 |
| 电磁门锁 | 继电器 + 锁 | BLE2 | NFC 验证通过时通电解锁 5 秒 |
| 六轴 IMU | MPU6050 | anchor | 检测车辆被擦碰（加速度突变）|
| 全彩 LED | WS2812B ×3 | anchor | 状态指示灯：绿=开门/授权，红=关门 |
| 擦碰上云 | ESP32 | **thingscloud** | 收到 anchor 擦碰信号后连 WiFi 上报 ThingsCloud → 微信预警 |
| 中枢 | 树莓派 5 | — | 跑 Qt UI 与任务调度、Python 人脸识别与录像 |
| 摄像头 | USB 摄像头 ×4 | 树莓派 | 车周四区录音录像、人脸识别 |

> 全系统共 **6 块 ESP32**（BLE1/BLE2/BLE3/anchor/tag/thingscloud）+ 1 块树莓派。

## 三、逐节点物理接线表（引脚级）

> ESP32 引脚均为 GPIO 编号。`↔` 表示双向，`→` 表示信号方向。所有设备**必须共 GND**。

### 3.1 anchor —— 车端主控 ESP32（BLE 名 `ESP32_MASTER1`）

| 外设 | 外设引脚 | ESP32 GPIO | 总线/说明 |
|---|---|---|---|
| DW3000 UWB | RST | **27** | 复位 |
| | IRQ | **34** | 中断输入（仅输入脚）|
| | CS/SS | **5** | SPI 片选 |
| | SCK | **18** | SPI 时钟 |
| | MISO | **19** | SPI |
| | MOSI | **23** | SPI |
| MPU6050 IMU | SDA | **21** | I2C（地址 0x68，400kHz）|
| | SCL | **22** | I2C |
| WS2812B 灯带 | DIN | **25** | 3 颗灯 |
| 擦碰信号输出 | → thingscloud GPIO4 | **4** | 数字输出，擦碰时拉高 |
| 串口 UART2 | TX | **17** | → 树莓派 RX |
| | RX | **16** | ← 树莓派 TX |
| BLE（板载） | — | — | 作为 Client 连 **BLE3** |
| 电源 | 5V / GND | — | |

### 3.2 tag —— 车主 UWB 标签 ESP32

| 外设 | 外设引脚 | ESP32 GPIO | 说明 |
|---|---|---|---|
| DW3000 UWB | RST/IRQ/CS/SCK/MISO/MOSI | **27 / 34 / 5 / 18 / 19 / 23** | 与 anchor 相同接法 |
| 开门按键 | 一端→GPIO，另一端→GND | **4** | INPUT_PULLUP，按下=开门 |
| 关门按键 | 一端→GPIO，另一端→GND | **25** | INPUT_PULLUP，按下=关门 |

### 3.3 BLE1 —— 雷达节点1 ESP32（BLE 名 `ESP32_SLAVE_1`）

## 四、BLE 级联拓扑（谁连谁）

3 个雷达节点 + 主控是**菊花链（daisy-chain）**：每个下游节点作为**上游节点的 BLE 客户端**订阅其数据，逐级把 3 个雷达目标汇聚到 anchor。

```
BLE1 ──▶ BLE2 ──▶ BLE3 ──▶ anchor
(Server) (中继)   (中继)   (纯Client)
```

| 节点 | BLE 角色 | 连接目标 MAC | 说明 |
|---|---|---|---|
| BLE1 | Server | — | 叶子节点，广播雷达1数据 |
| BLE2 | Client + Server | Client 连 `68:25:dd:f0:47:12`(=BLE1) | 汇聚雷达1+2 |
| BLE3 | Client + Server | Client 连 `6c:c8:40:56:19:22`(=BLE2) | 汇聚雷达1+2+3 |
| anchor | Client | 连 `68:25:dd:f0:59:32`(=BLE3) | 拿到全部 3 个目标 |

> ⚠️ **MAC 地址是硬编码的**：换板子后必须把新板 MAC 填到下游节点源码的 `slaveMacs[]` 里，否则连不上。

## 五、关键信号连线（跨节点的物理连线）

除 BLE/WiFi/UWB 无线链路外，需要用杜邦线物理连接的有：

1. **anchor UART2 ↔ 树莓派 UART**：anchor GPIO17(TX)→Pi RX，anchor GPIO16(RX)←Pi TX，GND 互连。
2. **anchor 擦碰信号 → thingscloud**：anchor GPIO4 → thingscloud GPIO4，GND 互连（一根信号线 + 共地）。
3. **各雷达 ↔ 对应 ESP32**：雷达 TX/RX 交叉接到 ESP32 GPIO16/17，雷达供电 + 共地。
4. **BLE2 继电器 → 门锁**、**BLE2 PN532 → I2C**：见 3.4。

> 供电建议：ESP32 与外设共 5V/3.3V 电源轨并**共 GND**；DW3000、LD2450、PN532 多为 3.3V 逻辑，注意电平匹配。

## 六、一步步实现步骤

1. **准备硬件**：6 块 ESP32、2 个 DW3000、3 个 LD2450 雷达、1 个 PN532、1 个 MPU6050、继电器+锁、3 个 WS2812、4 个 USB 摄像头、树莓派 5。
2. **按第三节接线**，逐节点连好、共地。
3. **用 PlatformIO 烧录固件**：`环境监测节点代码/` 下 BLE1/BLE2/BLE3/anchor/tag/thingscloud 各是独立工程，`pio run -t upload` 分别烧到对应板子。
4. **登记 MAC 并回填**：每块 ESP32 上电后串口会打印自己的 MAC；把 BLE1/BLE2/BLE3 的 MAC 依次填入 BLE2/BLE3/anchor 源码的 `slaveMacs[]`，重新烧录。
5. **配置云与网络**：改 `thingscloud/src/main.cpp` 里的 WiFi `ssid/password` 和 ThingsCloud 设备 Token / Project Key。
6. **部署树莓派**：装 Qt、`face_recognition`、OpenCV；把 `camera/` 放到 `/home/j/opendoor/`，车主照片放 `known_faces/`；使能 `/dev/ttyAMA0`。
7. **启动顺序**：先上电各雷达节点（BLE1→BLE2→BLE3）等 BLE 链建好 → 再上电 anchor 与 tag → 树莓派运行 `control_file.py` 和 Qt 程序 → thingscloud 上电联网。
8. **联调验证**：车主持 tag 靠近至 ~1m 看是否开门（WS2812 变绿）、远离 ~2m 关门；陌生人越线看摄像头是否录像；刷 NFC 卡看继电器是否解锁；敲击车身看 thingscloud 是否上报。

## 七、注意事项 / 已知点

- `thingscloud/src/main.cpp` 含明文 WiFi 密码与 MQTT Token，公开前请替换。
- anchor 的 `open_door` 等为原型级动作占位；UWB/人脸开门主要以串口指令 + WS2812 指示体现，物理门锁执行由 BLE2 继电器承担。
- 摄像头设备号注释与实际 `VideoCapture(0/2/4/6)` 存在命名错位，功能不受影响。
- LD2450 雷达默认 256000 波特率；anchor↔树莓派与调试串口为 115200。
