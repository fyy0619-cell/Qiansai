# 创新点总结

> 结合工程代码实际实现的机制，凝练本作品的核心创新点，供竞赛报告 / 答辩引用。

## 一句话凝练

> 本作品以 **UWB + 毫米波雷达的「身份-位置」融合鉴权**为核心，实现真正无感的车门交互；辅以分区电子围栏与「监控 / 录像分离」的隐私友好安防（陌生人越界只监控、仅异常才取证）、四重冗余开门、以及 IMU-云端联动的主动擦碰预警，构成一套分布式、多模态的智能汽车无感交互与安防系统。

---

## 一、核心创新：多模态融合的「身份 + 位置」双重感知

区别于普通无钥匙进入系统的本质创新点。

- **UWB 负责「是谁」，毫米波雷达负责「在哪」**：UWB 通过车主随身标签(tag)做厘米级双向测距，解决「靠近的是不是本人」；毫米波雷达探测车周所有行人的 X/Y 坐标，解决「人在什么方位、什么距离」。
- **交叉验证融合**：代码中用 `abs(雷达距离 − UWB距离) ≤ 0.8m` 关联两路数据——只有雷达目标距离与 UWB 测得的车主距离对得上，才认定「该雷达坐标即持标签车主」。单一传感器无法同时「定位 + 鉴权」，融合后才实现，天然抗「陌生人蹭开门」。

## 二、真正的「无感」交互

- **距离迟滞控制**：靠近约 1m 自动开门、远离约 2.65m 自动关门，开/关阈值不同并配 `flag` 状态位形成迟滞区间，避免临界点反复误触发。
- 全程无需掏钥匙、不碰车，比传统遥控/机械钥匙、乃至手机蓝牙钥匙更「无感」。

## 三、按方位分区的智能安防（电子围栏 +「监控 / 录像分离」）

- **象限分区触发**：车周按坐标象限分 4 区，哪个方位有陌生人越线就只唤醒对应那一路摄像头，而非四路全开——省算力、省存储。
- **「先监控、异常才录」的分级安防**：陌生人越界只唤醒摄像头做**实时监控预览、默认不录像**，人离开区域即自动关闭；**只有异常事件才触发录像取证**——目前由**剐蹭（IMU 加速度突变）**触发录像 + 云端预警，**黑名单人脸触发录像**为后续规划。普通路人只监控、不留存，**关键证据不漏、冗余录像不留**，兼顾取证、隐私与存储，比「无条件录像再删」更干净。

## 四、分布式多节点架构 + BLE 菊花链汇聚

- 3 个毫米波雷达分挂 3 块 ESP32、分装车身不同角度，经 **BLE 逐级级联(daisy-chain)** 汇聚多目标坐标至主控——用低成本无线组网解决多雷达多方位覆盖的布线难题，扩展性好。
- **边缘计算分层**：ESP32 端采集与预处理，树莓派端做 UI/调度/人脸识别，算力分层、职责清晰。

## 五、多重冗余的开门方式（一套系统四种入口）

UWB 无感开门 + 人脸识别开门 + NFC 刷卡 + 车钥匙按键，四种方式互为备份，兼顾「无感体验」与「极端情况可靠性」（如标签没电、识别失败时仍有 NFC/按键兜底）。

## 六、主动安防联动云端（擦碰即预警）

- MPU6050 IMU 检测车身加速度突变判定「被擦碰」，经一根信号线通知上云节点，通过 **ThingsCloud MQTT 推送微信预警**——将被动记录升级为主动实时告警，人不在车旁也能第一时间知情。
